# Product

## Register

product

## Users

Project Truth HRIS is used by admin and HR operators who manage HR workflows, configuration, workforce rules, attendance devices, and appliance/runtime operations. Admin configuration surfaces are owned by `hris-admin`; HR manager workflows apply only where the code or route explicitly targets HR work.

## Product Purpose

The product provides an HRIS and appliance runtime that can be verified from Windows host, VM/GitOps, LAN, and public Cloudflare paths. For product UI, success means operators can make configuration decisions quickly, understand runtime or policy state without ambiguity, and preserve evidence-backed operational truth.

## Brand Personality

Operational, direct, and trustworthy. The interface should feel like a working admin console for BNPI/Bandai HRIS: compact, legible, decisive, and calm under pressure.

## Anti-references

Avoid marketing-page styling, decorative dashboards, oversized hero layouts, nested decorative cards, generic SaaS gradients, and visual flourishes that obscure dense configuration work.

## Design Principles

- Task density with clarity: keep repeated operational controls compact, but preserve scanability and plain-language labels.
- Evidence over decoration: surface real counts, health, state, and validation messages instead of ornamental metrics.
- Familiar controls first: use standard tables, accordions, toggles, selects, and inputs consistently across admin screens.
- Admin role fidelity: admin configuration screens should read as `hris-admin` operational work, not HR manager self-service.
- Progressive disclosure: reveal detail through nested accordions or compact drilldowns when a flat table becomes too long.

## Accessibility & Inclusion

Target accessible product UI with keyboard-operable controls, visible focus states inherited from the component system, high-contrast text on neutral surfaces, and reduced-motion-safe state changes.
