# User Journeys

Status: INFERRED_FROM_EXISTING_PROJECT

## Admin Configures The System

1. Admin logs in.
2. Admin lands on the admin dashboard.
3. Admin configures organization structures such as departments, agencies, positions, levels, users, employees, schedules, holidays, workflows, devices, and guide content.
4. Admin reviews audit/activity logs for operational traceability.
5. Admin avoids production deployment, deletion, or secret actions unless explicitly approved.

## HR Manager Reviews Operations

1. HR manager logs in and lands on the role dashboard.
2. HR manager reviews approvals, operational queues, reports, employee status changes, attendance exceptions, recruitment, and payroll readiness.
3. HR manager approves, rejects, revises, or assigns work according to configured workflows.
4. HR manager validates sensitive changes before payroll, termination, transfer, or public-facing updates.

## HR User Handles Daily HR Work

1. HR user logs in and uses dashboard quick actions.
2. HR user manages employee records, documents, status-change requests, attendance corrections, timesheets, tasks, recruitment, onboarding, and reports.
3. HR user uploads/imports data where supported.
4. HR user escalates high-risk or policy-sensitive actions for approval.

## Employee Uses Self-Service

1. Employee logs in and lands on dashboard.
2. Employee views profile, requests, leave calendar, documents, payslips, attendance, payroll details, messages, and notifications.
3. Employee submits requests such as leave, overtime, document request, time adjustment, or personnel-related requests where available.
4. Employee tracks request status and responds to revision or follow-up.

## Employee Manager Reviews Team Work

1. Employee manager logs in and lands on manager-flavored dashboard.
2. Manager reviews pending approvals, team context, calendar, requests, and reports.
3. Manager approves or rejects team items according to policy.
4. Manager escalates HR-sensitive changes where needed.

## Timekeeper Logs Time

1. Timekeeper authenticates or reaches the time logging surface.
2. Timekeeper records or supports clock events.
3. Attendance records are created or updated.
4. Exceptions move into correction or approval workflows.

## Applicant Applies For A Job

1. Applicant opens public jobs.
2. Applicant views a job page.
3. Applicant completes a dynamic application form.
4. Application is submitted to recruitment workflow.
5. HR reviews the applicant record.

## Payroll User Runs Payroll Work

1. Payroll-capable HR user opens payroll, payroll periods, payroll settings, HR payroll, or billing surfaces.
2. User reviews employee, attendance, timesheet, leave, benefit, and salary inputs.
3. User processes or previews payroll according to configured rules.
4. Payslips and billing artifacts are generated or reviewed.
5. Production payroll behavior requires owner-confirmed rules and tests.
